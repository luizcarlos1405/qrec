Named scenes

Issue #3 · save the layers you set up under a name, and switch back to them at any time. Swamp Night, on the approved S02, S06 and S19 crops: only the onion layers panel, the menus and the dialogs are new.

What's on the board

  1. Live · named scene: a scene picker sits under the panel header, where Program puts the take banner. It shows a thumbnail of the layout and the scene's name. Variants: the menu open, and switching to a scene whose screen isn't connected.
  2. Onion layers panel, every state: no saved scene yet (Save as…), edited since loaded (a gold dot, Edited, a Save button and a dot on the changed layer), the scene menu, a scene's own actions (Rename, Replace with current scene, Duplicate, Delete…), renaming in place, Save as (with a name that's taken), a missing source, and while recording (picker locked).
  3. Program · apply a scene to a take: the take banner's Layout menu gets Apply a saved scene and Save this layout as a scene….
  4. Delete a scene: a confirmation, Cancel focused.
  5. Command palette: every saved scene is a command with its key and CLI form.

Calls made while designing

  • Scenes belong to the computer, not the project (~/.config/qrec/scenes.json), so a setup saved once works in every project, as presets do. The project still keeps its own scene in qrec.json, plus the name of the saved scene it came from, which is what drives Edited.
  • What a scene holds: the layers (source, rect, crop, opacity, fit, order, visibility, name) and the audio tracks (source, gain, mute, sync offset, the autocut track). Not the canvas size or fps: those belong to the project.
  • Switching replaces the project scene in one undoable command through Session::dispatch. Takes already recorded keep their snapshot. It's Live only, and locked while recording.
  • Edited compares the project scene with the saved one. Save overwrites it, the menu offers Save as new scene… and Revert to saved. The gold dot is a mark, not text (accent-2 stays out of text, DESIGN.md).
  • A missing source (DP-2 unplugged) doesn't block the switch. The layer stays in the scene with the error row, a dashed placeholder on the canvas and Replace… (pick another screen or camera). New takes record without it. A toast says so, with Undo.
  • Applying a scene to a take can only move what the take recorded. Layers are matched by source (screen output, camera device). Layers the scene lacks are hidden, the scene's extra layers are skipped, and a scene with no layer in common is disabled. One undo step.
  • Keys: Alt+1…9 use the first nine scenes in the menu's order (Live only). Alt is free apart from Alt+[ ] and Alt-drag.
  • Delete asks first. Saved scenes live outside the project's undo history, so a confirmation replaces Undo here. The title gets the swamp voice, the lead sentence the facts.
  • CLI: qrec scene save <name> [--update], qrec scene use <name> [--revert], qrec scene list, qrec scene rename <old> <new>, qrec scene rm <name>, all with --json, next to the existing qrec scene layer ….

Questions for you

1. Per computer, or per project?The design assumes per computer. Per project would drop the missing-source case and keep the scenes in the folder you share.
2. With a source missing, should Record still work?The design records without the missing layer. The alternative is to disable Record until it's replaced or removed, as S01a does with no sources.
3. Do scenes need a manual order?The design orders by creation, so Alt+1 stays stable. Dragging rows in the menu would let you choose which nine get a key.
4. Settled: the boards are the reference.The designs moved from qrec.pen to htmlboard on 2026-11-10, so once approved these boards are what the GTK views follow.
